Codex Relay 接入示例
默认模型：gpt-6-astra
默认推理档位：中档（medium）

一、通用客户端 / CC Switch 参数

选择支持 OpenAI Responses API 的客户端，填写：

配置          值
Base URL      https://relay.yanero.top/v1
API Key       自己的 userN.txt 中以 cr_ 开头的完整个人密钥
默认模型      gpt-6-astra
推理档位      medium（中档）
API 类型      Responses
用量管理      https://relay.yanero.top/

Base URL 填到 /v1 即可；客户端会追加 /responses。
每个人使用自己的个人密钥，管理员密钥用于管理页面。

二、Codex CLI 配置示例

在自己的电脑上编辑 ~/.codex/config.toml。
Windows 默认路径：C:\Users\你的用户名\.codex\config.toml
若设置了 CODEX_HOME，则编辑其目录下的 config.toml。
已有配置请合并修改同名项，保留自己的其他配置；顶层设置放在任何 [表名] 之前。

----- config.toml 示例开始 -----
model_provider = "yanero_relay"
model = "gpt-6-astra"
model_reasoning_effort = "medium"
web_search = "disabled"

[model_providers.yanero_relay]
name = "Yanero Relay"
base_url = "https://relay.yanero.top/v1"
env_key = "CODEX_RELAY_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
----- config.toml 示例结束 -----

先设置个人密钥，再从同一个终端启动 Codex。
下面的 cr_替换为自己的完整个人密钥 是占位符，必须替换。

Windows PowerShell（仅当前终端有效）：
$env:CODEX_RELAY_API_KEY = 'cr_替换为自己的完整个人密钥'
codex

macOS / Linux（仅当前终端有效）：
export CODEX_RELAY_API_KEY='cr_替换为自己的完整个人密钥'
codex

图形客户端若采用 env_key，也需要其进程能读取 CODEX_RELAY_API_KEY。
Windows 桌面版：搜索“编辑账户的环境变量”，新增用户变量
CODEX_RELAY_API_KEY，值为自己的完整个人密钥。
完全退出并重新打开 Codex；若仍读不到变量，可注销 Windows 后重新登录。
上面的 PowerShell 临时变量只影响该终端及其随后启动的子进程，
不保证从桌面图标启动的应用可以读取。
已有会话或项目级配置可能覆盖默认模型/档位；请新建会话并检查当前为 gpt-6-astra / medium。
不要将“示例开始/结束”分隔行、下划线前的转义反斜杠或 Markdown 链接写入 config.toml。

三、最小 Responses 请求示例

请求：POST https://relay.yanero.top/v1/responses
请求头：Authorization: Bearer cr_替换为自己的完整个人密钥
请求头：Content-Type: application/json
请求体：
{
  "model": "gpt-6-astra",
  "reasoning": {"effort": "medium"},
  "input": "请用一句话介绍你能怎样帮助我编写代码。",
  "stream": false
}

四、额度说明

每个人的用量持续累计，不再每周自动归零；由管理员手动重置或修改预算。
总生成并发为 6，个人默认 1；管理员可在后台将个人上限设置为 1–6。
客户端执行工具时不占生成槽，工具结果回传后重新排队。单会话顺序使用通常不会因个人并发 1 增加等待。
这不保证与官方登录完全相同；上游负载、限流和网关网络仍会影响速度。
管理员归零后历史统计仍保留，之后产生的新用量继续扣账。
本中转支持 Responses 子集；文件与命令工具在客户端电脑执行。
示例关闭服务端 web_search 和 WebSocket，使用 HTTP / SSE。
具体 Codex 版本的全部工具、远程压缩等功能兼容性仍取决于该版本发出的请求。
已验证网关 Responses 和客户端函数往返，尚未完成桌面版全部功能的端到端实测。

五、接入诊断

1. 先检查环境变量是否存在，不要输出密钥本身：
   PowerShell：Test-Path Env:CODEX_RELAY_API_KEY
   macOS / Linux：test -n "$CODEX_RELAY_API_KEY" && echo configured
2. 确认使用自己的个人密钥，Base URL 为 https://relay.yanero.top/v1。
3. 确认 model_provider 等顶层 TOML 配置位于第一个 [表名] 之前，并使用新会话。
4. 401 表示密钥失效或用户停用；429 请查看具体错误码，可能是预算不足、排队超时或队列已满。
5. 历史正文、图片与工具结果最多保留 7 天，每人 100 MiB，容量满时会提前清理。
   response_history_required 表示需由客户端提交完整历史；continuation_lost 表示等待中的工具会话已失效。
6. 经典格式带顶层 tools 且 parallel_tool_calls=false 目前不支持，会明确报错；没有工具的压缩请求可使用 false。

配置字段参考（OpenAI 官方文档）：
https://learn.chatgpt.com/docs/config-file/config-reference


Codex 新版 Responses Lite 兼容：接受首个 developer additional_tools 包装，将其中工具声明经过原有客户端工具校验与别名映射后使用，不把原名工具重复暴露给上游。Codex 在该协议自动发送 parallel_tool_calls=false；网关按协议适配，不能将此固定值视作用户要求工具串行。经典格式带顶层 tools 且 false 仍明确拒绝。此区别不影响全局及个人生成并发限制。
